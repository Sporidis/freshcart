Widgets & states

Fifty-eight frames is a lot of screens for what is, underneath, about fourteen widgets. This file inverts the board: instead of screens in flow order, every recurring piece is shown once with all the states it can be in — the unit a Flutter implementation actually builds.

What earns its own widget

It appears on three or more screens, or it has more than two states worth naming. Everything else is markup inside a screen. A "Shops on this list" row is not a widget — it is a SettingsRow with a switch. Resist inventing a widget per section; the list below is deliberately short.

Italicised entries — Stepper, ListSwitcher, ThemePreviewCard, InviteCard — are one-off compositions inside that single screen, not library widgets. They appear on one screen each, so by the rule at the top of this file they stay as markup; they are named here only so the composition is legible. If one ever turns up on a third screen, promote it.

Three widgets do most of the work — ProductRow, ShopTabPill and SettingsRow appear on nearly every screen. Build and test those three first; the rest of the app is assembly.
